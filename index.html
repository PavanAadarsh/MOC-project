Section 1: The One-Minute Explanation

Say this first

We model one Enigma rotor as a Mealy machine where each of the 26 states represents a physical rotational rotor position. Every key press outputs a scrambled letter and immediately advances the rotor to the next position. Crucially, the output character depends on both the current state and the specific key pressed.

Four things the machine demonstrates

Demonstration One-Sentence Meaning Live Data Trace Simulator Action
1. Same key, different output Pressing the exact same key repeatedly yields varying cipher outputs because the rotor advances each time. Input: "AAA" from q0 → Output: "JKC"
2. Rotor stepping Every keystroke deterministically advances the machine state from position qN to q(N+1). Input: "A" from q0 → Next State: q1
3. Full turn After exactly 26 keystrokes, the rotor completes a full 360-degree cycle and returns back to state q0. 26 keystrokes from q0 return to q0
4. Wrap-around Stepping is strictly modular: advancing from the final rotational position q25 wraps back around to q0. Input: "AA" from q25 → Output: "EJ"
Be upfront about this

This model implements the internal scrambling permutation and mechanical stepping of a single rotor only. It has no reflector and no plugboard, so it is not a full Enigma and does not by itself encrypt in a reversible reciprocal way. Historical cryptanalysis methods (the Turing-Welchman Bombe, clonking, Banburismus) are analyzed in our research paper review, but are not modeled by this finite state machine.

Why a Mealy machine and not a lookup table or if-statements?

A static program or simple lookup table cannot capture the computational properties of an Enigma rotor:

  • State-dependent output: The emitted cipher letter is a function of both current rotor position (state) AND input character (λ: Q × Σ → Γ).
  • State memory: The machine maintains historical context across key presses; a flat lookup table has no internal memory.
  • Strict determinism: For any given state and input letter, exactly one transition path and one output character exist.
  • Linear time execution: Processing n keystrokes takes O(n) time via constant-time O(1) table lookups per keystroke.
  • Explainable trace: The formal state trajectory demonstrates precisely how each ciphertext character was physically generated.
  • Formal rigor: As a standard theoretical automaton, it can be mathematically analyzed, proved complete, and tested for state equivalence and minimality.

Section 3: Formal Definition

In formal language theory, a Mealy machine is a 6-tuple:

M = (Q, Σ, Γ, δ, λ, q0)

Tuple Element Formal Name Definition in our Enigma Rotor Model
Q Finite set of states 26 states {q0, q1, ..., q25}, corresponding to the 26 rotational positions of the rotor.
Σ Input alphabet 26 uppercase Latin alphabet symbols {A, B, ..., Z} representing keys pressed on the keyboard.
Γ Output alphabet 26 uppercase Latin alphabet symbols {A, B, ..., Z} representing illuminated lampboard letters.
δ Transition function Total function Q × Σ → Q (676 entries). Advances the rotor cyclically: δ(qN, σ) = q(N+1) mod 26
λ Output function Total function Q × Σ → Γ (676 entries). In each state qN, λ(qN, ·) is a strict permutation of A–Z.
q0 Start state State q0 (the initial reference position of the rotor).
F Accepting states None (empty set ∅). A Mealy machine is a finite-state transducer that reads a finite input string and emits one output letter per input letter, with no accepting states. A short run, including an empty one, is valid.

From one rotor to the full machine

Three unconstrained 26-contact rotors yield 26 × 26 × 26 = 17,576 theoretical window positions. However, due to the middle rotor's mechanical ratchet double-stepping anomaly, only 26 × 25 × 26 = 16,900 states are physically reachable during continuous encryption (as documented in the paper review's addendum). Our project models a single rotor in isolation, which has exactly 26 rotational states (q0 to q25), with no window letters, no notch positions, and no ring settings.

Mealy Machine vs. Deterministic Finite Automaton (DFA)

Dimension Mealy Machine (Our Rotor) Standard DFA (Acceptor)
Primary Purpose Transducer: converts an input string into an output string. Classifier: decides membership in a formal language (w ∈ L).
Output Mechanism Emits an output symbol on every state transition (λ: Q × Σ → Γ). No transition outputs; emits only an Accept/Reject verdict upon string termination.
Accepting States No accepting states (F = ∅); every valid input character is processed. Designated set of final accepting states F ⊆ Q.
State Incompleteness Must be total (all 676 transitions defined) to encrypt all inputs. Can be partial, often implicitly routing undefined transitions to a dead state.

Section 7: What the Machine Computes

Because this machine is a transducer rather than a language acceptor, we do not describe a "language accepted" (which would be trivial: Σ*). Instead, we formally characterize the mathematical function f: Σ* → Γ* that it computes: a finite-state transducer that reads a finite input string and emits one output letter per input letter, with no accepting states. A short run, including an empty one, is valid.

Eight Core Computational Properties

  1. Complete: All 676 possible (state, letter) pairs are defined; no valid uppercase input is ever rejected or blocked.
  2. Deterministic: For every state and input character, there is exactly one next state and one output symbol.
  3. Per-state bijection: In every state, the mapping across all 26 input letters produces a permutation of A–Z with no duplicates and none omitted.
  4. Not self-inverse: Unlike a complete historical Enigma machine, this isolated rotor lacks a reflector; running the ciphertext through the machine a second time does not recover plaintext.
  5. Fixed points: In every state, exactly one letter is mapped to itself due to the internal pin wiring offset.
  6. Position matters: Polyalphabetic substitution ensures that repeated input letters map to different outputs as the rotor advances (e.g. AAA from q0 becomes JKC).
  7. Period 26: Stepping advances modulo 26, meaning the state sequence repeats cyclically every 26 keystrokes (q0 → q1 → … → q25 → q0).
  8. All 26 states are distinguishable: No two states share identical output substitution rows; thus the machine is minimal and cannot be reduced to fewer states.

A strength and a weakness, say both

Strength: Mathematical precision and absolute explainability—the transducer provides a deterministic, zero-ambiguity trace for every letter typed.

Weakness: Because this is only a single isolated rotor without a reflector or plugboard, it provides negligible cryptographic security and cannot decrypt reciprocally by re-running ciphertext. The model in this project contains no window letters, no notch positions, and no ring settings; the natural theoretical extension studied in cryptanalysis is cascading three rotors with turnover notches, a reflector, and a permutation plugboard.

Section 9: Theory Points a Teacher May Probe

Key theoretical distinctions and viva questions on finite automata and computability theory:

1. Is it really a Mealy machine?
Yes, it strictly satisfies the mathematical definition of a Mealy machine. It possesses a finite set of 26 states Q, finite input and output alphabets Σ = Γ = {A, …, Z}, a total state transition function δ: Q × Σ → Q, an output function λ: Q × Σ → Γ whose values depend directly on both current state and input symbol, and a designated start state q0.
2. Complete vs. partial machine
Our machine is completely defined: every one of the 26 × 26 = 676 possible state-input pairs has an explicit transition and output. The machine's input alphabet is strictly Σ = {A, …, Z}, so characters outside this set are not inputs to it and are refused by the input check before the machine moves. Because every valid key A to Z deterministically advances the rotor, the transition function δ is total, with no undefined moves, no reject states, and no dead states.
3. Minimisation and state equivalence
Using the standard table-filling equivalence partition algorithm, two states p and q are equivalent (p ≡ q) if and only if for all input strings w ∈ Σ*, λ̂(p, w) = λ̂(q, w). Since every state has a distinct 1-length output vector across the 26 input letters, no two states are 1-equivalent. Consequently, all 26 states are pairwise distinguishable, proving that the machine is already minimal and cannot be reduced.
4. Mealy vs. Moore vs. DFA
In a Mealy machine, outputs are associated with transitions (λ: Q × Σ → Γ), allowing immediate response to input keys. In a Moore machine, outputs are tied solely to states (λ: Q → Γ); any Mealy machine can be converted to an equivalent Moore machine, but doing so generally inflates the state count (up to |Q| × |Γ| states). A DFA produces no stream of outputs at all, providing only a binary accept/reject verdict at the end of input.
5. Computational complexity
Simulation requires O(n) time complexity for an input string of length n, because each character requires a single O(1) constant-time transition table lookup. Memory complexity for execution is O(1) auxiliary space, since only the single scalar state variable must be maintained. When storing the full diagnostic trace of all visited states and step records, the trace buffer consumes O(n) space.
6. What it cannot do (Theoretical limitations)
Because finite state automata lack unbounded external memory (like a stack or Turing tape), this machine cannot recognize non-regular languages such as anbn or count unboundedly. Furthermore, it cannot perform cryptanalysis or simulate the Turing Bombe search spaces (2,109,120 combinations for German Army/Air Force Enigma, or 11,811,072 for Navy). Those cryptanalytic searches are finite combinatorial brute-force problems whose difficulty lies in exponential search time rather than computational undecidability.

Section 10: Implementation Details

One source of truth for the machine

All machine states, alphabet definitions, the initial state, and all 676 transition cells are declared exclusively in enigmaData.js. The web application never hard-codes machine constants; every stat tile, trace, and table across this study guide dynamically queries this single source of truth at page load.

How the implementation works

The system is constructed with zero frameworks, zero bundlers, and zero external runtime dependencies:

  • enigmaData.js: Contains the single source-of-truth JavaScript object defining states, alphabets, start state, and the complete 26 × 26 transition lookup table.
  • validator.js: Implements automated assertion checks that verify state counts, completeness (676 transitions), cyclic stepping qN → qN+1, and output bijectivity.
  • enigmaMachine.js: Contains the pure simulation function runEnigmaMachine that evaluates input strings without side effects or global mutations.
  • test.js: Automated Node.js test suite running 19 exhaustive test cases covering rotor stepping, wrap-around, full cycles, and character validation.
  • index.html: Semantic, accessible HTML5 structure providing the complete study guide interface across all 11 sections (Sections 0 through 10).
  • style.css: Pure vanilla CSS implementing responsive typography, high-contrast academic aesthetics, and print media rules.
  • app.js: Lightweight vanilla browser script that reads machine data, calculates live traces, populates DOM elements, powers the interactive state diagram, transition matrix, state profiles, the step-by-step interactive simulator with text cleaning and auto-play, and the live worked traces verification table, and executes 19 automated startup self-checks in the browser console.

How to run the tests

To run the automated verification suite offline, open a terminal in the project directory and execute:

node test.js

The terminal executes the 4-rule data validator and all 18 simulation test cases in test.js, concluding with TEST SUMMARY: 19/19 match (19 of 19: 1 validator case and 18 simulation cases), while the browser console executes 19 automated runtime self-checks, concluding with All System Self-Checks PASSED (19/19).

Simulation Function Return Structure

The pure execution function runEnigmaMachine takes the machine data, an input string, and an optional start state (defaulting to q0). It returns a structured result object containing:

  • output: The resulting ciphertext string formed by concatenating each emitted character.
  • visitedStates: The ordered array of all states visited during execution, beginning with the start state.
  • finalState: The state where the rotor rests after processing the final input character.
  • steps: An array of step objects, each recording the active state, input letter read, output letter generated, and destination state.
  • error: A descriptive error message detailing the offending character and its 1-based position if an invalid token is encountered, or an empty string for valid runs.
